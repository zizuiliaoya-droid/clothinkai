## 2. 写代码必须避开的坑

数据库与迁移
- `text()` 里的绑定参数一律写 `CAST(:x AS type)`；`jsonb_build_object` 的键也要 `CAST(:key AS text)`
- 约束名会被命名约定套前缀（`ck_promotion_ck_promotion_xxx`），按名字查 `pg_constraint` 时要注意
- 生成列（Computed）要给模型加 `__mapper_args__ = {"eager_defaults": True}`，否则 async 下会 `MissingGreenlet`
- `INSERT … WHERE NOT EXISTS` 里同一参数出现两次会类型歧义，改用 `ON CONFLICT DO NOTHING`；`UPDATE … FROM LATERAL` 引用不到目标表，改用相关子查询
- 可空列上的唯一键要 `NULLS NOT DISTINCT`：用 `op.execute` 写原生 DDL，ORM 侧不要再声明
- 改了已经跑过的 migration，本地库不会重跑：先 downgrade 再 upgrade
- 改汇总表的列或口径，迁移里要清空 `report_summary_coverage`
- 「先删后插」不能并发：用租户级 `pg_try_advisory_xact_lock`；测并发要两条独立连接（`session` fixture 是单连接）
- 新 model 的 FK 目标表要在 model 模块里显式 import，否则只在 Celery 路径上炸；检查要起干净子进程，不能靠 conftest

权限
- `has()` 的前缀通配只看第一段、action 精确匹配。新 scope 要么用独立一级域（如 `promotion_ship`），要么用通配捞不到的 action 名
  （如 `refresh`）。起名前先查现有通配和持有者（生产：pr / pr_manager 有 `promotion.*:*`；pr_manager / operations 有 `report.*:read`；
  operations 有 `product.*:read`）
- 自审、两级不同人这类规则，通配挡不住，只能在 service 层挡

ORM、校验与接口
- 类里有名为 `list` 的方法时，返回注解要写 `builtins.list`
- `text(...).columns(*Model.__table__.columns)` 配 `scalar_one_or_none()` 拿到的是第一列（id）；要取实体就用 `select(Model)`
- `session.expire_all()` 或 service 层 `rollback()` 之后再读 ORM 属性会 `MissingGreenlet`：先把要比的 id 取出来
- 可清空的可选字段，用 `payload.model_fields_set` 判断有没有传，不要用 `is not None`
- 加硬约束时，状态机先判，附加门槛后判
- 手写的列名清单迟早会烂（推广列表漏过 5 列）：能从 `__table__.columns` 反推就反推
- 上传一律后端代传（浏览器直传 R2 需要桶的 CORS，测试测不到）
- 配置收编后要清掉所有写死的副本；读取方法的阈值参数不给默认值，漏传就直接报错
- 依赖「今天」的派生值，不能当成历史数据冻结

测试
- 测试绿了不等于有效：等值测试要加「场景有效性」断言（各指标都出现非零值）；写完做故障注入，确认会红
- 比较两条数据路径用 `model_dump(mode="json")` 逐字比，不比 Decimal（`0` 和 `0.00` 在页面上不一样）
- 可加的指标逐日存精确值，取整留到求和之后；ORDER BY 要有唯一的兜底键
- 测试工厂从 PR #36 起对不认识的 kwarg 直接 `TypeError`：加列时先把 kwarg 补进 `tests/conftest.py` 对应工厂的 `_KNOWN_KWARGS`；批量建单要显式给足随机位数
- 读导入数据的代码，测试要从真实导出的样子开始走 adapter（中文表头、千分位、`-` 占位、多余列），不要手写落库后的行
- 「先跑一遍全量」的测试会掩盖「从没被刷过」的边界：增量逻辑要有一条不做前置准备的用例
- 模块级 `pytestmark = [..., pytest.mark.asyncio]` 会误伤同步测试：纯规则测试放 `tests/unit/`

## 3. 做事方式（少做重复功，效果不打折）

- 读：先 grep 定位，再按行号读需要的段落；读过的大文件把要点记进笔记或进度文件，不要反复整读。超过 50 KB 的文档只读简报点名的小节
- 写：每完成一个小节或一个条目就落盘；进度写进简报指定的计划或 FEAT 文件，中断后靠它续跑；步骤结束前读回确认
- 测：先写能复现问题的测试（改前是红的）→ 修 → 故障注入确认会红 → 全量 + lint + 前端三件套。这几步都不能省
- 评审：只看本轮改动；HIGH / MEDIUM 才要求改，NIT / LOW 记下来顺手改，不为它们开新一轮
- 范围：只做简报里的条目；发现简报外的问题写进报告，不要顺手扩大改动
- 提交：只在自己的分支上本地提交；中文提交信息，写成文件再 `git commit -F`；只 add 自己改的文件；不 push、不开 PR、不改台账（这些由编排方做）
- 不连生产、不读密钥（`deploy-secrets.local.md`、`backend/.env`）；有影响大的歧义时 send_message(severity warning) 问编排方
