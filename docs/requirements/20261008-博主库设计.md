## 3. 简报第 3 节九个问题的决定

### 3.1 列名：不改（K2）

改名会让生产已存的自定义映射（`target_field = "xiaohongshu_id"`）静默失效、`audit_log` 历史键对不上，还要动索引、`ON CONFLICT`、四个 adapter、前端与两个在途分支，换来的只是名字好看。只改索引名、界面文字、提示与注释（「平台账号，历史原因叫 xiaohongshu_id」）；API 不加 `account` 别名。

### 3.2 唯一键迁移：§4（新键 = 旧键加一列，必成立；谓词与 `ON CONFLICT` 的 `index_where` 一字不差）

### 3.3 抖音走哪条通道：新来源 `huitun_douyin`，用 `manual_blogger` 的引擎（K3）

- 不扩 `manual_blogger`：灰豚导出没有平台列只能猜；两行表头与手工模版混在一起；映射按来源存，一个来源只能一套
- 不扩 `huitun`：它只更新已有小红书博主画像、不建博主、写死 OVERWRITE，改成建博主 + COMPARE 等于换掉在用来源的语义
- 新来源：判重 / 补空 / 冲突 / 同批第一行为准 / 裁决全复用，平台固定抖音，导入记录可分开看。`manual_blogger` 另改：平台进判重键并校验枚举、表头改「账号」、加「主页链接」（§6.2）

### 3.4 抖音 38 列：§6.3、§6.4

### 3.5 博主类型对抖音

`blogger/tag_config.py` 加 `TYPE_GRADED_PLATFORMS = frozenset({"小红书"})`。`service.py::create_blogger`、`update_blogger`（改粉丝数时）、`tag_service.py::recompute_for_tenant` 只对集合内平台自动分级；其余平台的 `blogger_type` 保持手填 / 导入值，重算不碰（质量标签、假号照常重算）。导入照旧不重算。生产全是小红书，行为不变。抖音阈值等业务方给，届时加阈值并把抖音放进集合。

## 5. 权限与标签字典（8b-3）

### 5.1 新 scope `blogger_tag:write`

`has("blogger_tag", "write")` 只在持 `*`（admin、platform_admin）、精确持 `blogger_tag:write`（pr_manager）、持 `blogger_tag.*:*|write`（没人）时为真。PR / 主管的 `blogger.*:*`、运营的 `blogger.*:read` 前缀是 `blogger` ≠ `blogger_tag`，捞不到；叫 `blogger.tag:write` 就会被 PR 的通配命中。读字典用现有 `blogger:read`。个人授权覆盖照常可用。

### 5.2 存储：复用 `dict_item`

`dict_type = 'blogger_tag'`：表、RLS、唯一索引、备份都现成。代价是商品字典接口挂 `product:read/write`（跟单、运营有），要挡：`product/dict_models.py` 加 `RESERVED_DICT_TYPES = frozenset({"blogger_tag"})`，`product/dict_api.py` 列表排除保留类型、新增 → 422 `DICT_TYPE_RESERVED`、删除 `WHERE dict_type NOT IN (…)`（等于没找到）。（有护栏测试）。

### 5.4 系统标签只读、类目标签按字典（service 层挡）

`BloggerService._check_tags(payload, blogger | None)`，在 create / update 里排在「存在 → 唯一性 → 字段写权限」之后：
- `quality_tags`：create 传了非空、或 update 传了且归一后与库里不同 → 422 `BLOGGER_SYSTEM_TAG_READONLY`。只有重算写它
- `category_tags`：只看**新加的**（新值 − 库里的值）：含系统标签词 → 422 `BLOGGER_SYSTEM_TAG_READONLY`；不在启用字典里 → 422 `BLOGGER_TAG_NOT_IN_DICT`（`details.tags`，标签不敏感）。旧标签（含字典里已删的）可留可去
- 字典查询一条 `value = ANY(CAST(:tags AS text[]))`；导入同口径（§6.6）。放在 service 是因为要查库、要和当前值比

### 6.4 数值解析 `importer/cn_numbers.py::parse_cn_number(raw) -> Decimal | None`

- `None` / 占位符（`compare.is_placeholder`）→ `None`；`bool` → `ValueError`；`int` / `float` → `Decimal(str(v))`
- 字符串：去所有空白（含 NBSP）与千分位 `,` `，`，全匹配 `^[+-]?(\d+(\.\d+)?|\.\d+)(w|W|万|亿)?$`，`w/W/万` ×10⁴、`亿` ×10⁸；否则 `ValueError("数值格式不正确")`（不含值）。不认 `k`、`%`、科学计数法、`1.2w+`、区间
- 粉丝数：`ROUND_HALF_UP` 取整，0 ≤ n < 2³¹；报价：再过 `compare.check_money`

## 9. 错误处理与输入校验

| 操作 | 失败条件 | 性质 → 调用方收到 |
|---|---|---|
| 建 / 改 / 恢复博主 | （平台, 账号）被未删除的博主占用 | 致命 → 409 `BLOGGER_XHS_ID_CONFLICT`，`details{platform, xiaohongshu_id, existing_blogger_id}` |
| 建 / 改博主 | 账号不合 pattern 或超长；主页链接非法；网页ID > 64；报价备注 > 500 | 致命 → 422（pydantic） |
| 建 / 改博主 | 传了非空报价备注，但没有报价写权限（含个人授权） | 致命 → 403 `FIELD_PERMISSION_DENIED`（`field="quote_note"`，D3） |
| 读博主 | 没有报价读权限 | 报价备注与报价一样给 `null`（列表、详情、导入失败明细、冲突明细同样遮挡） |
| 建 / 改博主 | 改系统标签；类目标签新加系统标签词或字典外的词 | 致命 → 422 `BLOGGER_SYSTEM_TAG_READONLY` / `BLOGGER_TAG_NOT_IN_DICT`（`details.tags`） |
| 并发建同键 | 预检后插入撞唯一索引 | 与现状一致：500，error 进 Sentry（不在本次范围） |
| 字典 增 / 删 | 无 `blogger_tag:write` | 403 |
| 字典 增 | 空 / > 32 字；系统标签；已存在 | 422；422 `BLOGGER_TAG_RESERVED`；409 `BLOGGER_TAG_EXISTS`（审计只记成功的） |
| 字典 删 | 不存在 / 非本类型 | 404 `BLOGGER_TAG_NOT_FOUND` |
| 商品字典接口 | 新增保留类型 | 422 `DICT_TYPE_RESERVED`；删除保留类型 = 没找到 |
| 导入一行 | 账号 / 博主ID / 昵称空（抖音写明「博主ID为空…未导入」）；账号不合正则（「账号只能包含字母、数字、_ . -」）；平台不在枚举；粉丝数解析不了或为负；超长 | 行失败，失败明细原因不含受保护值 |
| 导入一行 | 同批博主ID 相同、网页ID 与第 M 行不同 | 整行不导：「重复已跳过」+ 行提示（D1②） |
| 导入一行 | 抖音报价不是单一数字 | 不算错：原文照写报价备注，只是不写报价，不提示（§6.3） |
| 导入一行 | 抖音报价原文 > 500 字；链接非法；同批后面的行某字段与先前不同 | 可恢复：丢这一格、行提示，行照常 |
| 导入一行 | 质量标签列有值 | 可恢复：不写，整批提示一次 |
| 导入一行 | 类目标签字典外 / 系统词 | 可恢复：丢掉，整批提示一次，汇总见 `/api/blogger-tags/missing` |
| 缺标签汇总 | 指定的批次不存在 / 看不到 / 非博主来源 | 404 `IMPORT_BATCH_NOT_FOUND`；不传 `batch_id` 且没有可看的 `manual_blogger` 批次 → 200 空清单 |
| 导入整批（抖音 xlsx） | 没有「抖音博主库」sheet 或「博主ID」表头（`XlsxLayout.required`，r1 N10） | 致命：批次 failed，`error_summary`「没有找到『抖音博主库』sheet 或『博主ID』表头，请上传灰豚导出的原文件」，不报 Sentry |
| 推广单导入一行 | 按（推广平台, 账号）找不到，且账号在 ≥ 2 个平台都有未删除的博主 | 行失败「账号 X 在多个平台都有博主（…），请把「平台」列填成博主所在的平台」（§3.9）；只在 1 个平台有 → 用它，行照常；都没有 → 照旧「博主 X 不存在」 |
| 冲突裁决 | 旧冲突的平台 / 质量标签选覆盖 | `invalid_value`，可改选保留 |
| 迁移 | upgrade 新键预检重复；downgrade 同账号跨平台 | 致命：事务回滚，日志 `[059]` 写明原因与数量 |
| 迁移 downgrade | 待处理冲突引用 `web_id` / `homepage_url` / `quote_note` 或来源是 `huitun_douyin` | 不中止：置 `invalid` + `resolution_note`，日志 `[059]` 打印行数（§4.3 第 3 步） |
| 迁移 downgrade | `huitun_douyin` 批次的导入原文含「微信号」「报价」（旧代码遮不住，r2 M4） | 不中止：从 `import_job.raw_data` 去掉这两个键，日志 `[059]` 打印行数（§4.3 第 4 步） |

不变量归属：（平台, 账号）唯一——索引兜底、service 预检；平台取值——schema 枚举 + adapter（库里不加 CHECK，沿用现状）；系统标签只读与字典约束——service 与 adapter（要查库）；字典维护权——路由；保留字典类型——`product/dict_api.py`。

## 11. 生产只读核对 SQL（编排方合并前 / 后跑）

```sql
-- P1 平台 × 软删（预期 小红书 / false / 2037）
SELECT platform, is_deleted, count(*) FROM blogger GROUP BY 1, 2 ORDER BY 1, 2;
-- P2 平台为空（预期 0）
SELECT count(*) FROM blogger WHERE platform IS NULL OR btrim(platform) = '';
-- P3 新键重复（预期 0 行）
SELECT tenant_id, platform, xiaohongshu_id, count(*) FROM blogger WHERE NOT is_deleted GROUP BY 1, 2, 3 HAVING count(*) > 1;
-- P4 只差大小写 / 空白的同号（预期 3 组 6 行）
SELECT tenant_id, platform, lower(btrim(xiaohongshu_id)), count(*) FROM blogger WHERE NOT is_deleted GROUP BY 1, 2, 3 HAVING count(DISTINCT xiaohongshu_id) > 1;
-- P5 不合新 pattern 的账号（这些博主在界面上改不了，现状问题，报告给业务方）
SELECT count(*) FROM blogger WHERE xiaohongshu_id !~ '^[A-Za-z0-9_.\-]+$';
-- P6 / P7 标签非空的博主（10-08 预期 0 / 0；不为 0 说明有人写过，迁移不种字典，要另议）
SELECT count(*) FILTER (WHERE category_tags <> '[]'::jsonb), count(*) FILTER (WHERE quality_tags <> '[]'::jsonb) FROM blogger;
-- P8 博主待处理冲突按字段（看平台 / 质量标签 / 粉丝数各几条）
SELECT f->>'field', count(*) FROM import_conflict c, jsonb_array_elements(c.fields) f WHERE c.object_type = 'blogger' AND c.status = 'pending' GROUP BY 1;
-- P9 博主来源的自定义映射
SELECT source, count(*) FROM field_mapping WHERE source IN ('manual_blogger', 'huitun') GROUP BY 1;
-- P10 / P11 新 scope 与字典类型不撞（预期 0）
SELECT count(*) FROM permission WHERE scope LIKE 'blogger\_tag%';
SELECT count(*) FROM dict_item WHERE dict_type = 'blogger_tag';
-- P12 推广单平台分布（看有多少推广单的发布平台 ≠ 小红书；这些行今后重导时靠 §3.9 的回落找到博主）
SELECT platform, count(*) FROM promotion GROUP BY 1 ORDER BY 2 DESC;
```

合并后：`alembic_version` = 059；`pg_indexes` 里 `blogger` 的 `uq_blogger%` 只有 `uq_blogger_platform_account`；持 `blogger_tag:write` 的角色只有 pr_manager；`dict_item(blogger_tag)` 为 0 行（主管建字典前）；`information_schema.columns` 里四个新列（`web_id`、`homepage_url`、`platform_metrics`、`quote_note`）都在。

## 12. 风险

- R1 样本博主ID 不唯一（94 组 / 203 行，10 组网页ID 不同）：同 ID 同网页ID 的后续行只提示；网页ID 不同的整行不导并提示（D1②），跨批进冲突（D1①）；那 10 组是不是不同的人已转业务方，若是，唯一键要再议

- R6 「带货型」对抖音仍用爆文阈值 1000 → 属 7e-7
- R7 在途分支冲突 → §8
- R8 报价备注表单项按默认角色显隐，个人授权放开 / 收回报价写权限的人前端看到的可能不准 → 以后端校验为准（403 / 读不到给 `null`）
