## 5. 权限与标签字典（8b-3）

### 5.1 新 scope `blogger_tag:write`

`has("blogger_tag", "write")` 只在持 `*`（admin、platform_admin）、精确持 `blogger_tag:write`（pr_manager）、持 `blogger_tag.*:*|write`（没人）时为真。PR / 主管的 `blogger.*:*`、运营的 `blogger.*:read` 前缀是 `blogger` ≠ `blogger_tag`，捞不到；叫 `blogger.tag:write` 就会被 PR 的通配命中。读字典用现有 `blogger:read`。个人授权覆盖照常可用。

### 5.2 存储：复用 `dict_item`

`dict_type = 'blogger_tag'`（`blogger/tag_dict.py::BLOGGER_TAG_DICT_TYPE`）：表、RLS、唯一索引、配置备份都现成。代价是商品字典接口挂 `product:read/write`（跟单、运营有），要挡：`product/dict_models.py` 加 `RESERVED_DICT_TYPES = frozenset({"blogger_tag"})`，`product/dict_api.py` 列表排除保留类型、新增 → 422 `DICT_TYPE_RESERVED`、删除 `WHERE dict_type NOT IN (…)`（等于没找到）。护栏测试断言常量在集合里。

### 5.3 接口（`blogger/api.py`，服务 `blogger/tag_dict.py::BloggerTagDictService`）

| 端点 | 权限 | 行为 |
|---|---|---|
| `GET /api/blogger-tags` | `blogger:read` | `{items: [{id, value, sort_order}], system_tags, can_manage}`，按 `sort_order, value` 排；`can_manage = perms.has("blogger_tag", "write")`（前端据此显隐，不硬编码角色） |
| `POST /api/blogger-tags` | `blogger_tag:write` | `{value, sort_order?}`：value 去空白后 1 ~ 32 字；系统标签 → 422 `BLOGGER_TAG_RESERVED`；已存在 → 409 `BLOGGER_TAG_EXISTS`；`sort_order` 0 ~ 9999；审计 `blogger_tag.create` |
| `DELETE /api/blogger-tags/{id}` | `blogger_tag:write` | 不存在 / 非本类型 → 404 `BLOGGER_TAG_NOT_FOUND`；**不动**博主身上已有的标签；审计 `blogger_tag.delete` |

不做改名与拖动排序。系统标签不进字典表，由 `tag_config.py::SYSTEM_TAGS`（两个现有常量）给出，谁都删改不了。

### 5.4 系统标签只读、类目标签按字典（service 层挡）

`BloggerService._check_tags(payload, blogger | None)`，在 create / update 里排在「存在 → 唯一性 → 字段写权限」之后：
- `quality_tags`：create 传了非空、或 update 传了且归一后与库里不同 → 422 `BLOGGER_SYSTEM_TAG_READONLY`。只有重算写它
- `category_tags`：只看**新加的**（新值 − 库里的值）：含系统标签词 → 422 `BLOGGER_SYSTEM_TAG_READONLY`；不在启用字典里 → 422 `BLOGGER_TAG_NOT_IN_DICT`（`details.tags`，标签不敏感）。旧标签（含字典里已删的）可留可去
- 字典查询一条 `value = ANY(CAST(:tags AS text[]))`；导入同口径（§6.6）。放在 service 是因为要查库、要和当前值比

### 6.4 数值解析 `importer/cn_numbers.py::parse_cn_number(raw) -> Decimal | None`

- `None` / 占位符（`compare.is_placeholder`）→ `None`；`bool` → `ValueError`；`int` / `float` → `Decimal(str(v))`
- 字符串：去所有空白（含 NBSP）与千分位 `,` `，`，全匹配 `^[+-]?(\d+(\.\d+)?|\.\d+)(w|W|万|亿)?$`，`w/W/万` ×10⁴、`亿` ×10⁸；否则 `ValueError("数值格式不正确")`（不含值）。不认 `k`、`%`、科学计数法、`1.2w+`、区间
- 粉丝数：`ROUND_HALF_UP` 取整，0 ≤ n < 2³¹；报价：再过 `compare.check_money`

## 9. 错误处理与输入校验

| 操作 | 失败条件 | 性质 → 调用方收到 |
|---|---|---|
| 建 / 改 / 恢复博主 | （平台, 账号）被未删除的博主占用 | 致命 → 409 `BLOGGER_XHS_ID_CONFLICT`，`details{platform, xiaohongshu_id, existing_blogger_id}` |
| 建 / 改博主 | 账号不合 pattern 或超长；主页链接非法；网页ID > 64 | 致命 → 422（pydantic） |
| 建 / 改博主 | 改系统标签；类目标签新加系统标签词或字典外的词 | 致命 → 422 `BLOGGER_SYSTEM_TAG_READONLY` / `BLOGGER_TAG_NOT_IN_DICT`（`details.tags`） |
| 并发建同键 | 预检后插入撞唯一索引 | 与现状一致：500，error 进 Sentry（不在本次范围） |
| 字典 增 / 删 | 无 `blogger_tag:write` | 403 |
| 字典 增 | 空 / > 32 字；系统标签；已存在 | 422；422 `BLOGGER_TAG_RESERVED`；409 `BLOGGER_TAG_EXISTS`（审计只记成功的） |
| 字典 删 | 不存在 / 非本类型 | 404 `BLOGGER_TAG_NOT_FOUND` |
| 商品字典接口 | 新增保留类型 | 422 `DICT_TYPE_RESERVED`；删除保留类型 = 没找到 |
| 导入一行 | 账号 / 昵称空；平台不在枚举；粉丝数解析不了或为负；超长 | 行失败，失败明细原因不含值 |
| 导入一行 | 报价非单一数字；链接非法；标签字典外 / 系统词；质量标签列有值；同批后面的行与先前不同 | 可恢复：丢这一格、行提示，行照常 |
| 导入整批 | sheet 不在 → 用活动 sheet；找不到「博主ID」行 → 第一个非空行当表头（各行「博主ID不能为空」） | 可恢复：partial / failed + 失败明细 |
| 冲突裁决 | 旧冲突的平台 / 质量标签选覆盖 | `invalid_value`，可改选保留 |
| 迁移 | upgrade 新键预检重复；downgrade 同账号跨平台 | 致命：事务回滚，日志 `[059]` 写明原因与数量 |

不变量归属：（平台, 账号）唯一——部分唯一索引兜底，service 预检给提示；平台取值——接口靠 `Platform` 枚举（schema），导入靠 adapter（库里不加 CHECK：谈款 / 推广单的平台是自由文本，沿用现状）；系统标签只读与字典约束——service 与 adapter（要查库）；字典维护权——路由 `require_permission("blogger_tag", "write")`；商品字典接口不碰保留类型——`product/dict_api.py`。

-- P5 不合新 pattern 的账号（这些博主在界面上改不了，现状问题，报告给业务方）
SELECT count(*) FROM blogger WHERE xiaohongshu_id !~ '^[A-Za-z0-9_.\-]+$';
-- P6 要种进字典的类目标签：去重个数 / 超 32 字 / 系统标签词
SELECT count(DISTINCT btrim(t)) FILTER (WHERE char_length(btrim(t)) BETWEEN 1 AND 32 AND btrim(t) NOT IN ('高性价比','带货型')) seed,
       count(*) FILTER (WHERE char_length(btrim(t)) > 32) too_long, count(*) FILTER (WHERE btrim(t) IN ('高性价比','带货型')) sys
FROM blogger b, jsonb_array_elements_text(CASE WHEN jsonb_typeof(b.category_tags) = 'array' THEN b.category_tags ELSE '[]'::jsonb END) t
WHERE NOT b.is_deleted;
-- P7 质量标签里系统标签以外的值（预期 0）
SELECT t, count(*) FROM blogger, jsonb_array_elements_text(quality_tags) t WHERE t NOT IN ('高性价比','带货型') GROUP BY 1;
-- P8 博主待处理冲突按字段（看平台 / 质量标签 / 粉丝数各几条）
SELECT f->>'field', count(*) FROM import_conflict c, jsonb_array_elements(c.fields) f WHERE c.object_type = 'blogger' AND c.status = 'pending' GROUP BY 1;
-- P9 博主来源的自定义映射
SELECT source, count(*) FROM field_mapping WHERE source IN ('manual_blogger', 'huitun') GROUP BY 1;
-- P10 / P11 新 scope 与字典类型不撞（预期 0）
SELECT count(*) FROM permission WHERE scope LIKE 'blogger\_tag%';
SELECT count(*) FROM dict_item WHERE dict_type = 'blogger_tag';

## 12. 风险

- R1 样本博主ID 不唯一（94 组 / 203 行，10 组网页ID 不同），与「唯一」的说法不符；同批后面的行只提示不覆盖，若真是两个人会被并成一个 → D1；网页ID 是比较字段，跨批不同会进冲突
- R2 48 行没有博主ID，整行失败 → 报告写明，补齐后「重试失败行」
