## 设计时必须记得的坑（台账「踩过的坑」节有全文）

- 权限 `has()` 的通配：前缀通配只看第一段（`promotion.*:*` 会命中任何 `promotion.xxx:yyy`），
  action 精确匹配。**新权限的一级域和 action 名直接决定它会不会被已有通配捞走**（谈款审核当初就是
  因此独立成 `negotiation` 一级域）。给新动作起名前查一遍谁持有哪些通配
- 全系统有一批查询按 `settlement_status = '已付款'` 过滤（索引、汇总、财务列表），往这个枚举里
  加值 / 改语义要列出全部受影响的查询
- 任何改汇总表列或口径的 migration 都要清空 `report_summary_coverage`（054 定下的规则）
- 手写列名清单会烂（`list_with_cte` 漏 5 列的教训）；测试工厂对不认识的 kwarg 静默忽略
- 置换单没有 settlement 行（`approve_barter` 不发 `SettlementRequested`）
