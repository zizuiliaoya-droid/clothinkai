# 谈款驳回原单重提与七天取消

2026-11-16 业务调整，覆盖 1007 流程设计中「主管驳回为终态、复制新谈款」的旧规则。

- 主管驳回后仍显示「审批未通过」。本人在最近一次主管驳回后 168 小时内可修改、重新提交，单号和主线不变；提交后重新从主管审核开始，仍需老板审核。
- 到第 168 小时即不再允许修改或重提。现有 Celery 每 5 分钟扫描，将仍处于「审核驳回」的单据改为「已取消」，不删除单据、评论和历史，不生成推广单。只读查询不触发取消。
- 编辑、评论不延长七天期限；重新提交后退出本轮倒计时，再被主管驳回时按新驳回时间计时。老板退回仍沿用原流程。
- 旧单没有 `reviewed_at` 时使用现有 `updated_at`；首次编辑把编辑前的锚点固定到 `reviewed_at`，避免被编辑刷新。没有事件的旧单首次重提时，将已有真实审核信息同事务补成一条历史事件，不做全库回填。
- 停用所有状态的「复制为新谈款」动作。旧复制来源、事件和路由保留，旧路由返回状态不允许错误。
- 审核弹窗及原单时间线保留各轮驳回原因、人员和时间；博主卡片按驳回事件显示最近五次与总次数，重提、审核通过、取消后不丢失旧原因。原有可见范围与金额权限不变。
- 「已取消」退出在谈、待跟进统计；尚未取消的驳回单仍属待推进。

实现：`077_negotiation_rejection_cancel` 接 `076_negotiation_creation_keys`，仅扩展谈款状态 CHECK，不增加字段或改历史值。存在「已取消」业务数据时禁止降回 076，应通过应用回退或前进修复处理，不能把取消单改回驳回来迁就旧约束。

任务：`app.tasks.negotiation_tasks.cancel_rejected_negotiations`，beat key `cancel-rejected-negotiations`，默认队列，每五分钟执行；按租户独立事务处理，条件更新与重提竞争时只允许一个状态结果，取消事件与更新一起提交。

验证：规则矩阵、168 小时边界；原单多轮重提与历史保留；旧单锚点；过期拒绝、重复扫描、真实租户 RLS 与两连接重提/取消竞争。077 的升降往返与真实数据库检查复用现有 CI 阶段。
