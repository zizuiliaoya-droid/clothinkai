## 停止与回退条件

- 版本 / 制品SHA不符、迁移失败、ACL / RLS不符、DB / Redis不健康、worker / beat异常或关键业务核对不符时，停止后续切换并记录已生效范围；不能只凭 `/ready` 成功认定可继续。
- 执行前审查旧应用版本与新schema是否兼容，以及是否已有不可逆业务写入；仅在兼容且获批时按本轮方案回退应用。若需恢复数据库，须明确恢复点后的数据损失和附件引用影响，确认已有批准明确覆盖该恢复操作，未覆盖则另获生产写入批准；不得盲目downgrade或恢复旧备份覆盖新数据。
- 旧单PG恢复点、试运行容器及旧Zeabur数据保留不等于可直接切回；回退目标、入口、角色、任务唯一运行和备份格式兼容均须先核实。没有自动恢复或已配置外部报警的验收证据。

本次开发候选含068内容分类与069旧周/月缓存清理，尚未获新合并/生产批准。069降级只恢复空缓存表及原索引/RLS/ACL，不恢复缓存数据；后续升级方案须明确这一边界，日汇总与报表口径保持原有实现。
