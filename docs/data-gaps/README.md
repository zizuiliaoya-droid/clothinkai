# 数据缺口台账

记录「数据已导入但进不了报表」的情况，以及各自的原因和处理方式。数据补齐之后
对应条目可以删掉。

## 千牛链接映射缺口（2026-09-25 盘点）

投产报表的销售额来自千牛日报，日报要靠 `platform_product`（千牛链接）关联到款式
和商品。链接缺失的日报就不会出现在报表里。

盘点时 310 条千牛日报中有 106 条找不到链接，合计 ¥96,006.40 —— 报表只看到全部
销售额的 47%。按千牛日报 `extra` 里的「货号」字段分类：

| 原因 | 链接数 | 支付金额 | 处理 |
|---|---|---|---|
| 货号精确匹配款式货号 | 35 | ¥25,474.00 | migration 039 已自动补 |
| 货号多了字母前缀（`MY2026001` → `2026001`） | 1 | ¥327.90 | migration 039 已自动补 |
| 款式未在系统建档 | 49 | ¥62,854.50 | migration 040 已建最小档案，类目待人工核对 |
| 千牛后台未填货号（导出为 `-`） | 14 | ¥7,350.00 | 见 `千牛未填货号清单.csv`，需人工 |

> 盘点时把 `NH2602`～`NH2605`、`NH022`、`MY011` 这 6 个归为「货号填成批次号」，这个
> 判断是错的：它们各自对应不同品类的具体商品（`NH2602` 是波点针织半身裙、
> `NH2603` 是牛仔阔腿裤），而且系统里本来就有 `NH01x`、`MY00x` 这种长度 5 的款号
> 格式。它们是款号，只是没建档，已随 040 一起建。

万相台日报的 `extra` 没有货号，只有「主体ID」（即淘宝商品ID），所以靠同
`platform_id` 的千牛链接带出归属。盘点时 16 条悬空、¥2,306.81，039 补了 9 条
¥1,863.40。

### 已建最小档案的 49 个款式要补什么

migration 040 从千牛日报反向建档，只填了货号、款名、上下架状态、品牌，外加**推断的
类目**。这些款式的 `remark` 里标了来源与推断依据，在款式管理里按货号搜就能找到。

待人工补齐：

- **类目**：按款名推断，规则是「套装」全名优先，其余先看款名前 20 字再看全名
  （淘宝标题末尾爱堆关键词，`...收腰衬衫女长袖花边拼接显瘦通勤上衣外套` 结尾是
  「上衣外套」但主体是衬衫，只看全名会判成外套）。准确率不是 100%，建议抽查。
- **季节**：一律留空。
- **SKU 与成本价**：没有。成本价缺失会让套装成本、单件货品成本算不出来。
- **主图**：没有。

`未建档款式清单.csv` 保留了建档时的原始依据（千牛商品ID、商品名称、商品状态、
支付金额），核对时可以对照。

**千牛未填货号的 14 条**：要人工判断。其中两条本身不对应单个款式 ——
`750458195077`（补差价专用）和 `988564242366`（双十一惊喜福袋合集），建议保持不
映射，否则会把不属于某款的销售额算进该款投产比。

## 历史推广记录的发布状态（2026-09-25 记录）

5156 条推广记录里 5154 条 `publish_status` 是「未发布」，报价合计 ¥1,105,028。
投产报表的站外推广费只统计「已发布」，所以那一列基本为 0；工作进度报表的发文率
同理偏低。

这批是环境重建时补录的历史数据，源表只有报价金额、合作日期、款式、博主，**没有
实际发布日期、发布链接、点赞数**，状态只能落在「未发布」。经业务确认保持现状，
不批量改状态（改了等于编数据）。

## 款式货号里混入部件名（2026-09-25 发现）

`style.style_code` 里存在 `2026038内里`、`2026039外套` 这类值 —— 货号字段混进了
部件名。任何按货号对接的外部数据（千牛、万相台、供应商）都会在这里匹配失败。
建议把部件信息挪到款名或备注，货号保持纯编码。
