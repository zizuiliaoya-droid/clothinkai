# 平台管理与客户只读排查

系统持有人使用独立的平台账号。平台账号登录后进入 `/platform`，管理客户开通、启停及只读排查；客户管理员进入自己的 ERP。不要把平台账号交给客户，也不要给客户的 `admin` 追加平台身份。

## 开通客户

1. 在平台客户列表点「新增租户」，填写客户名称、唯一租户代码和客户的初始管理员账号。
2. 创建成功后保存弹窗中的登录链接、租户代码、管理员账号和临时密码，私密交给该客户。临时密码只显示一次。
3. 客户第一次登录修改密码，新租户没有旧客户的业务数据；不同客户都可以使用 `admin` 作为管理员名。
4. 客户管理员管理自己租户的员工及业务角色，不能维护平台账号；客户用户列表也不会显示平台账号。

「停用」保留客户数据，并使该客户原登录失效；重新启用后需重新登录。目前历史 `default` 内仍存有旧客户数据和平台账号，本版不提供该租户的整体停用；新建客户可以正常启停。

## 只读排查

平台持有人在客户列表选择只读排查后，只查看本次选定客户的数据。页面持续显示客户名称与只读提示，可搜索、筛选、翻页，并可返回平台。

只读排查不能新增、修改、删除、审批、上传或执行业务任务。平台正常会话也不能直接进入原客户业务页面处理数据。凭据、采集令牌和其他未开放的功能不在排查入口内；导航只展示已支持的查询页面。

排查会话最长15分钟，没有刷新令牌。返回平台、会话失效或刷新页面后退出排查，并清理客户查询缓存；原平台登录保留，不会替客户注销其登录。排查使用独立的支持会话，不需要知道客户密码。平台身份、目标客户状态或安全戳变化后，原排查会话失效。

系统记录实际平台操作人与目标租户。业务查询继续按目标租户隔离，后端只放行已核对的查询接口，业务数据库事务为只读；界面隐藏按钮不能替代这些后端限制。

## 平台身份和运维初始化

平台身份由保留的 `platform_admin` 角色成员关系判定，普通管理员角色和个人 `*` 授权不能代替。财务、PR主管等客户业务角色仍可组合。

平台开户、启停和只读排查遵守已有个人拒绝权限。平台身份不开放在普通用户角色选择器中，后端拒绝通过普通创建用户、角色分配接口增删该身份。

新增平台持有人属于明确的运维授权操作，不随应用升级自动执行。需要初始化时，先确认账号由系统持有人掌握，再用已有 `app.modules.auth.grant_platform_admin` 在受保护运行环境预览目标；实际授予仍须批准。不要照搬历史 `default/admin` 示例，原客户管理员不能作为平台持有人。

杭州当前已完成平台与客户账号分离：系统持有人使用 `default/platform_owner`，旧客户使用 `default/admin`。本功能升级保留两者的密码和既有角色，不再次执行身份初始化。

本版共用现有应用和服务器，不增加套餐计费、自助注册、可写的客户支持模式或跨租户集中员工管理。
