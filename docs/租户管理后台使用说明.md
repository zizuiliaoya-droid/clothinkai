# 租户管理后台

平台管理员登录后，在左侧「系统管理 → 租户管理」操作。普通客户管理员只管理自己租户的账号和业务数据，不会获得租户管理能力。

## 开通一个客户

1. 点「新增租户」，填写客户名称、租户代码和初始管理员账号。代码使用 1–64 位字母、数字、下划线或短横线，页面不提供改码。
2. 创建成功后，弹窗显示该客户的登录链接、租户代码、初始账号和临时密码。密码只显示这一次，请私密交付给客户；关闭后不能查看原密码。
3. 客户使用链接登录，第一次必须修改密码。新租户为空，业务账号、单据及附件记录不会从默认租户复制；不同租户可以都使用 `admin` 账号。
4. 同一个租户代码不能重复开户，也不会覆盖已有客户。

「停用」保留数据，但该客户所有账号不能登录。重新启用后必须重新登录，停用前的登录状态不会恢复。`default` 保留为平台管理租户，不能在页面停用。

## 角色与平台身份

财务、PR 主管等业务角色仍可组合。平台管理员身份是单独的保留角色成员关系，只在 `default` 租户生效；个人授权的 `*` 和普通「管理员」角色都不能代替它。

平台身份仍遵守个人拒绝优先：列表需要 `auth.user:read`，开户和启停需要 `auth.user:write`；拒绝 `*` 或对应权限会阻断操作。

普通用户角色下拉不会出现平台管理员，后端也拒绝通过创建用户、分配角色增删该身份。平台账号的重置密码、启停、解锁、资料、业务角色和个人权限只允许平台管理员维护。平台管理员编辑自己的业务角色后需要重新登录。

## 运维首次初始化

初始化不会自动随升级执行。本轮建议目标为 `default/admin`，实际生产授权与执行由上线确认单明确批准。

在应用的受保护运行环境中，使用现有系统数据库连接执行预览，目标环境和数据库名称必须与当前配置一致：

```sh
python -m app.modules.auth.grant_platform_admin \
  --username admin \
  --expect-environment production \
  --expect-database <实际生产数据库名>
```

确认预览目标并取得本次操作授权后，再在同一命令增加 `--apply`。工具只追加既有 `platform_admin` 角色，保留原密码与全部业务角色，并使该账号旧登录失效；重复执行不会重复添加。执行会记录审计，不输出数据库密码。

杭州容器的运行配置由已有保护程序注入，普通 `docker exec` 不继承启动子进程环境。实际执行必须通过现有受保护配置读取入口，不要把密码复制到命令行，也不要将上面的示例当作未经检查即可执行的发布指令。

本功能没有套餐、计费、配额、自助注册或跨租户业务浏览。创建租户只返回初始凭据，后续忘记密码仍走已有账号恢复流程。
