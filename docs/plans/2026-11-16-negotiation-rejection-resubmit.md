# 审批未通过：原单重提与七天取消

## 用户目标与当前问题

2026-11-16 客户要求：审批未通过时不再复制新谈款；只能在原单重新提交审核，或七天后自动取消，以便保留并查看历史驳回原因。

当前 main `1cef746` 把审核驳回设为终态，仅允许复制；系统没有谈款取消状态或自动取消任务。重提流程可复用老板退回已有实现；审核时间线已记录多轮事件，但旧数据无事件时仅依赖当前审核字段，需在首次重提清空字段前保存真实历史。

## 执行口径

- 保持原谈款 id、line_id 和负责人，在“审批未通过”打开原单修改，提交后回“主管待审”。保存修改仍保持审批未通过，不新建草稿。
- 移除当前复制入口，后端也不接受从驳回单复制；历史 copied_from_id 和复制事件继续可读。
- 七天暂按最近一次主管驳回起连续 168 小时执行，已向用户提出该推荐口径。保存不重置；及时重提后停止倒计时；再次驳回重新计时。若用户纠正则同步修改，不把未回复记为确认。
- 到期变为“已取消”，原单和历史保留，不允许编辑、重提或复制。到期检查复用 Celery 定时机制，最多约五分钟内落为取消；写接口到期即拒绝重提，避免定时检查间隙绕过。取消与提交争用同一行，只允许一个状态转移成功。
- 主管审核弹窗、驳回单编辑弹窗展示历史原因、审核人和时间，复用已有时间线事件。博主卡片的驳回记录按真实事件计数，重提/通过/取消后仍可查阅；沿用原权限。
- 旧单缺事件时，仅在原单首次重提的同一事务保存已有真实驳回字段，不做全库历史回填。旧 reviewed_at 为空以旧 updated_at 作为锚点，首次编辑将该锚点固定，避免保存延长时限。

## 最小实现与验证

新增“已取消”枚举及 077 CHECK 约束迁移、自动取消事件与任务；复用 edit/submit、现有权限矩阵和时间线，不新建流程配置平台或历史表。取消后的记录不算进行中合作。

覆盖原 id 重提、多轮历史保留、七天边界、编辑不重置、重提与取消竞争、跨租户隔离及已取消只读；同步状态矩阵快照、前端菜单/弹窗测试，完成一次交叉独评和当前提交 CI。无关模块不扩大改造。
