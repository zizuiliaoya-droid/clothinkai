# 网页租户管理最小设计

在 main 04f8da7 上补齐平台管理员的租户列表、新增、启用与停用，不扩套餐、计费、配额或租户切换。

采用现有 Role/UserRole 中的保留角色 `platform_admin`，并要求成员属于启用的 `default` 租户。租户管理按数据库中的明确角色成员关系检查，不由 `*` 或个人权限 grant 推导。复用已有成员关系、认证与会话机制，无需新表。

普通角色接口不能改变 platform_admin 的成员关系；平台账号的密码重置、状态、角色和个人权限修改都验证调用者平台身份。已有平台成员可保持该角色不变并调整业务角色。初始授权只通过运维入口，追加角色而不覆盖原 admin，更新安全戳并吊销旧会话；不在启动或迁移时自动授权，实际目标 default/admin 需写入后续批准单。

新增租户复用原子开户服务，返回租户、管理员用户名和仅本次可见的随机临时密码；首次登录仍强制改密。UI只把密码留在本次成功弹窗，关闭或身份变化后清除。停用/启用使用明确状态请求；停用后现有 access/refresh 无效，启用后重新登录。default 是平台控制租户，不能通过页面停用。

沿用现有 Ant Design 表格、表单和确认弹窗，新增“系统管理 → 租户管理”入口。客户 admin 不显示入口，直接调用 API 同样 403。测试覆盖真实 DB 中平台/客户边界、保留角色分配和平台账号保护、开户原子性及停用恢复，前端覆盖入口、成功凭据清除、错误与状态操作。独立评审由另一代理完成；本轮不直接合并或上线。

## 权限语义补充

租户管理以真实平台成员为额外门槛，列表复用 `auth.user:read`，开户/启停复用 `auth.user:write` 的 EffectivePermissions 检查，遵守个人拒绝优先。没有新增权限种子、迁移或权限框架。
