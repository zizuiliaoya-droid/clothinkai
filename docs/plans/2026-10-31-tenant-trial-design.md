# 多租户内测与角色权限补齐

2026-10-31 用户授权：“可以补齐，尤其是多租户”。基线为已上线 main `f2fb3e281c83b531f27a90495100fbf17d1c4695`、数据库 069。本轮是新增内测准备，原 1007 已交付记录保留。

## 目标与选择

支持少量独立租户共用杭州部署，各有管理员和业务数据；同名账号能按租户登录，审计记录不串租户。已有账号可直接组合“财务＋PR 主管”，个人拒绝优先于角色授权。

选择现有租户模型、行级隔离、角色多对多关系与个人覆盖机制，补齐入口和明确缺口。全局不重复用户名只能临时约束，不能解决租户自行建用户后的冲突，故登录显式加入租户代码。当前用运维开户工具建立测试租户，不新增完整平台管理、套餐、计费、自助注册或跨租户切换体系。

## 租户登录与开户

- 登录请求增加可选租户代码，省略或空白继续使用 default；前端中文提示保留原客户登录习惯，并支持带租户代码的分享链接。
- 后端先确定有效租户，再查该租户用户名。未知或停用租户不暴露账户存在性；失败计数区分租户。刷新与正常访问检查必要租户状态，避免停用后仍可继续使用。
- 运维开户命令明确目标环境；一次事务创建租户、租户管理员和关联角色。重复代码不覆盖已有客户，失败不留下半个租户。
- 初始随机密码只在成功结果中返回，首次登录强制修改；命令不接收、记录客户已有密码，也不自动连接生产。
- 普通管理员只管理自己租户的用户，不能通过新增公共开户接口创建其他租户。

## 隔离与权限

- 审计记录列表及计数都加当前租户条件；没有租户上下文则拒绝查询。请求参数不能决定目标租户。
- 保留业务表既有租户过滤和 RLS；本轮不因某表没有 RLS 而扩大重构。
- 已有用户角色修改复用后端替换列表接口，界面显示中文并允许多选；实际授权决定操作入口，不能仅看角色名字。角色改变后按既有机制重新登录。
- 个人拒绝与通配授权的优先级统一处理；检查后端直接 scope 消费、字段权限、有效权限返回和缓存，防止一处修复、另一处绕过。组合角色仍遵守禁止自审、老板终审等既有业务约束。

## 验收与交付

两路独立 worktree 实施，在集成前各进行针对性验证；完成后交叉独立评审，修复明确问题，不做无目标的反复全量审查。真实数据库验收利用现有 GitHub CI，不把生产数据库作为测试环境，也不修理本机 Docker/WSL。

必须覆盖：旧 default 登录；两个租户同名账号；跨租户用户/审计列表与计数；开户重复与失败回滚；停用租户；两角色组合；无权修改角色；单项拒绝覆盖整组授权；恢复默认；前端保存失败与重新登录。

root 负责集成、GitHub、脱敏进度同步和发布材料；子代理实现业务代码。开发完成后形成可审阅的 PR、CI 结果和开户说明，再依既定流程请求合并及生产升级授权。本轮没有授权真实开户或 ERP 生产写入。
