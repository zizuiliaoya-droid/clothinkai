# 1118 谈款与推广补充需求审阅与实施

依据用户提供的《谈款与推广_两条补充需求_20261116.md》，对照 main `5f353d8`（077 已上线）审阅。两条业务需求可直接执行，无待确认业务口径；本批不改数据模型，不新增迁移或定时任务。

## 审阅修正

- 谈款提交当前有七项卡点，不是六项。颜色尺码同时存在后端能力矩阵和前端自查校验，只删后端一项不足以满足需求。款式、博主、合作模式、平台、约定发布时间、服务费维持现有提交规则；服务费沿用后端档案报价解析，不额外增加前端空值限制。
- 草稿、新建提交、老板退回重提、审批未通过原单重提统一取消颜色尺码的提交卡点；077 的驳回历史和 168 小时规则保持。
- 颜色尺码暂缺不等于接受不匹配的 SKU。用户选择了 SKU 时仍校验归属；缺失或部分缺失时按现有定稿逻辑不复制不完整的发货明细，推广页推送仓库前补齐并执行原硬校验。
- 推广当前快捷项有 14 个，其中部分是角标和完结条件，不应全部变成阶段枚举。仅阶段类快捷项从共享阶段定义选取；在“超时”前加入“档期内”，保留其他类型快捷项。
- 后端阶段过滤及计数已共用派生阶段 SQL 并包含“档期内”，不新增计数实现，不落库，不改变租户催发阈值。
- 五列从列表可用列定义中移除，旧列偏好也不能恢复它们。内部编码和内容分类在详情保留，内部编码仍可搜索，内容分类筛选保留；实际“对接 PR”与隐藏的历史“负责 PR”字段区分。

## 实现范围

1. 前后端移除谈款颜色尺码提交必填；款式标签改为“提交审核前必填”；缺颜色尺码显示黄色提示，主管/老板审核摘要显示灰字提醒。
2. 推广增加“档期内”快捷筛选及计数，移除内部编码、内容分类和三项历史录入列；复用现有列偏好过滤机制和阶段来源。
3. 必要回归覆盖缺 SKU 提交与重提、两级审核摘要、定稿后仓库拦截、缺款/发布时间/服务费继续拦截；推广覆盖快捷筛选计数、五列不可选、内部编码搜索/详情与内容分类筛选保留。
