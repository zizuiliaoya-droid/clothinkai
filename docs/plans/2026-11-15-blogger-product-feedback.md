# 1115 博主库与商品款式反馈

本轮基于 main `92cfb6b`。客户确认问题发生于杭州环境：新建博主在填写保存后提示请求校验失败；谈款问题是新建时找不到已认领博主。

## 采用的规则

1. 新建博主、单笔谈款默认抖音；编辑已有资料保留原平台。平台沿用当前系统枚举，不新增微博或移除得物。
2. 博主列表隐藏报价、画像更新时间、是否假号，保留报价备注及原数据。历史指标折叠保留其他指标，只移除假号相关展示。账号组合报价、导入报价不受影响。
3. 博主模板使用通用账号、博主昵称、平台列。旧租户映射通过有效映射兼容处理，保留其他自定义列和旧表头别名，不重置配置。平台缺失、空白或非法均行级报错；旧无平台文件须补平台或重新下载。
4. 博主表单在提交前校验账号格式、有效昵称长度和整数粉丝数，并展示可操作的字段错误。保持后端约束和认领要求。
5. 单笔谈款先选平台，再选该平台可合作的博主；切换平台清除旧博主选择。认领不改变已有单据负责人或赋予审核权限。
6. 商品/套装与款式保留各自用途。规格成本放入款式视图，旧成本路由仍可达；既有 SKU 多规格成本和商品成员成本的算法保持。
7. 商品与款式页统一提供商品资料导入、空白 XLSX 模板、列说明、映射和冲突处理。模板每行是一个规格，款号和 SKU 编码按文本处理；不新增套装成员关系导入。原读取、导入权限保持。

## 为什么需要兼容旧映射

当前内置博主模板已有平台字段，但生产 default 保留的有效映射仍是七列小红书旧映射，没有平台。只修改默认模板不能解决客户问题。因此下载和解析使用相同的兼容规则，且不覆盖租户保存的配置。

现有成本表有商品资料导入和列说明，但原来没有真正的空模板下载。本轮在已有 XLSX 生成机制中补齐，而非新增独立 CSV 导出逻辑。

## 验收范围

- 旧租户映射下载模板后填一行，按真实适配器解析；抖音、小红书及跨平台同账号按现有唯一键区分。平台缺/空/非法明确失败。
- 表单非法输入在提交前阻止或返回明确字段提示；新建与编辑的平台规则分别验证。
- 已认领抖音博主在新建谈款可选，原编辑平台、单据可见性和审核权限不变。
- 旧成本路由可达，多规格成本可读，导入权限不扩大；导入完成刷新商品、款式、SKU 和成本视图。
- 无数据库迁移、无新增项目依赖、无历史业务数据修正。合并及杭州生产升级另按用户授权执行。

具体测试结果、CI 和评审记录以本批 PR 当前提交为准。客户当时的完整 B6 请求未提供，构造的校验失败用例不等于已确定其唯一输入原因。
